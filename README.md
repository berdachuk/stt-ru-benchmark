# Русский STT: свои GPU против Deepgram и GigaAM

Открытый замер точности распознавания русской речи. Шесть движков, один и тот же
набор файлов, одна нормализация, доверительные интервалы, построчные результаты.

Повод: **публичных цифр WER по русскому у Deepgram нет** — ни в документации, ни
в маркетинге. Есть общий показатель 5.26 % (англоцентричный) и заявление «мы
лучше Whisper на 7 языках из 7» без раскладки. Поэтому измерили сами.

*English summary: an open WER/CER benchmark of Russian ASR — self-hosted Whisper
large-v3-turbo vs Deepgram Nova-2/Nova-3 vs GigaAM v3 on FLEURS-ru. Identical
audio bytes, identical normalization, bootstrap confidence intervals, per-sample
transcripts published so anyone can recompute.*

## Результаты

**FLEURS-ru (test), 150 сэмплов, 28.4 минуты аудио.** Интервалы — бутстрап по
высказываниям, 1000 реплик.

| движок | WER | 95 % ДИ | CER | WER + нормализация чисел | n |
|---|---:|---|---:|---:|---:|
| Deepgram **nova-2** | **3.70 %** | [2.88; 4.64] | 1.13 % | 3.67 % | 150 |
| **Whisper large-v3-turbo** (свои GPU) | 3.74 % | [2.86; 4.66] | **1.02 %** | 3.70 % | 150 |
| WhisperX-пайплайн (тот же turbo) | 3.74 % | [2.86; 4.66] | 1.02 % | 3.70 % | 150 |
| **GigaAM v3** | 4.16 % | [3.18; 5.25] | 1.15 % | 4.08 % | 140 |
| Deepgram **nova-3** | 6.51 % | [5.06; 8.17] | 4.42 % | **4.60 %** | 150 |
| Whisper-turbo, RU файн-тюн | 8.65 % | [7.28; 10.17] | 1.80 % | 8.41 % | 150 |

Попарные разницы на **одних и тех же** высказываниях (интервал, накрывающий ноль,
означает, что разница не доказана):

| пара | разница | 95 % ДИ | вывод |
|---|---:|---|---|
| nova-2 − Whisper turbo | −0.03 п.п. | [−0.89; +0.81] | **разница не доказана** |
| GigaAM − nova-2 | +0.45 п.п. | [−0.30; +1.22] | **разница не доказана** |
| GigaAM − Whisper turbo | +0.33 п.п. | [−0.41; +1.10] | **разница не доказана** |
| nova-2 − nova-3 | −2.80 п.п. | [−4.25; −1.64] | значима |
| Whisper turbo − RU файн-тюн | −4.92 п.п. | [−6.19; −3.76] | значима |

### Выводы

**1. Три движка неразличимы на этой выборке.** Deepgram nova-2, self-hosted
Whisper large-v3-turbo и GigaAM v3 сидят в пределах 0.5 п.п., и **ни одна из
попарных разниц между ними не значима**. Утверждать, что коммерческий API точнее
своего железа (или наоборот), эти данные не позволяют.

**2. Отставание Nova-3 на две трети — формат записи чисел, а не слух.** Флагман
Deepgram пишет числительные словами, эталон FLEURS — цифрами:

```
эталон : в 1990 году он был добавлен в список всемирного наследия
nova-3 : в тысяча девятьсот девяностом году он был добавлен …          [WER 15%]
```

Нормализация числительных снимает **1.91 п.п. из 2.81**: 6.51 → 4.60, CER падает
с 4.42 до 1.82. Признак был виден сразу: у nova-3 CER всего вдвое ниже WER, тогда
как у остальных — втрое-вчетверо. Это известная ловушка, ей посвящена работа
[«What is lost in Normalization?»](https://arxiv.org/abs/2409.02449).

**3. Метрика может измерять баг.** RU-файн-тюн Whisper-turbo показал 8.65 % — но
он **вставляет пробел внутрь слова** при декодировании:

```
телевизион ные · обнаруж ены · передав аться · выб орочно · прив ести
```

Речь распознана верно, слово разорвано; для WER это двойной штраф. Дефект
встретился 62 раза на 52 из 150 сэмплов (35 %), у large-v3-turbo — один раз.
**8.65 % и есть продакшн-результат** — именно его получает пользователь.

<details>
<summary>Диагностика: какая часть WER приходится на дефект (oracle)</summary>

Если склеить разорванные слова, **сверяясь с эталоном**, WER падает до 4.36 %.
Это oracle-число с утечкой правильного ответа: так починить в проде нельзя.
Оно отвечает только на вопрос «какая доля ошибок — разрывы», и ответ: примерно
половина. В основную таблицу такое ставить нельзя.

Та же проверка по всем движкам показывает, что дефект — свойство одной модели,
а не артефакт метрики:

| движок | WER | после oracle-починки | разрывов | сэмплов задето |
|---|---:|---:|---:|---:|
| RU файн-тюн turbo | 8.65 % | 4.36 % | **62** | **52/150** |
| GigaAM v3 | 4.16 % | 4.01 % | 2 | 2/140 |
| Whisper turbo / WhisperX / nova-2 | — | — | 1 | 1/150 |
| nova-3 | 6.51 % | 6.51 % | 0 | 0/150 |

Воспроизвести: `python harness/split_bug.py "results/raw150/*.jsonl"`
</details>

**4. Пайплайн WhisperX не добавляет точности.** Прямой вызов и полный пайплайн
(VAD + выравнивание) дали **побайтово одинаковый текст на всех 150 сэмплах** —
разница WER ровно `0.00 [0.00; 0.00]`. Отличается только задержка: 1.18 с против
3.79 с, и та разница — загрузка файла, очередь и поллинг, а не распознавание.

## Скорость

Измерена отдельно и в одну таблицу с точностью не ставится: у движков разные
режимы вызова, а лейны боевые и шумят.

| движок | режим | медиана | RTF |
|---|---|---:|---:|
| Whisper large-v3-turbo | один POST | 1.18 с | 0.11 |
| RU файн-тюн turbo | один POST | 1.43 с | 0.133 |
| Deepgram nova-3 / nova-2 | один POST | 1.83 / 1.85 с | 0.171 / 0.223 |
| WhisperX-пайплайн | upload → очередь → поллинг | 3.79 с | 0.348 |

`RTF` — доля реального времени: 0.11 значит минуту аудио за 6.6 секунды.

## Как воспроизвести

```bash
pip install -r requirements.txt

# 1. собрать построчные транскрипты (каждый движок независимо)
K=<ключ>   python harness/run_bench.py --engine whisper-1 --limit 150
DG=<ключ>  python harness/run_bench.py --engine nova-2    --limit 150
RPA=<ключ> python harness/run_bench.py --engine gigaam-v3 --limit 150
SC=<токен> python harness/run_bench.py --engine speechcore --limit 150

# 2. добрать строки, где API вернул ошибку (иначе выборки разойдутся)
python harness/retry_failed.py "results/raw/*.jsonl"

# 3. метрики, интервалы, попарные разницы
python harness/analyze.py "results/raw/*.jsonl" --runs 1000
```

Сырые транскрипты — [`results/raw150/`](results/raw150/), сводка —
[`results/summary_150.json`](results/summary_150.json). Метрики считаются **из
них**, так что любой может пересчитать своей нормализацией, не тратя деньги на API.

## Методика

- **Набор**: [`google/fleurs`](https://huggingface.co/datasets/google/fleurs)
  ([Conneau et al., 2022](https://arxiv.org/abs/2205.12446)), `ru_ru`, сплит
  `test`, первые N сэмплов по порядку, без отбора.
- **Аудио**: те же самые исходные байты каждому движку, без пересжатия. Транспорт
  различается (multipart против raw body) — одинаковы именно байты.
- **Нормализация** (одинаково к эталону и гипотезе): нижний регистр, `ё→е`,
  снятие пунктуации, схлопывание пробелов. Смысл — штрафовать за неверно
  распознанное слово, а не за оформление; тот же принцип, что у
  [нормализатора Whisper](https://arxiv.org/abs/2212.04356) и
  [Open ASR Leaderboard](https://arxiv.org/abs/2510.06961).
- **Отдельная колонка с числительными**: числа прописью переводятся в цифры
  (`number-parser`). Она **дополняет** базовую, а не заменяет: для русского разбор
  неполный — количественные берутся, порядковые нет.
- **Метрики**: `jiwer`, корпусные WER и CER (сумма ошибок к сумме длин, а не
  среднее по сэмплам).
- **Интервалы**: бутстрап по высказываниям, 1000 реплик
  ([Bisani & Ney, ICASSP 2004](http://www-i6.informatik.rwth-aachen.de/PostScript/InterneArbeiten/Bisani_BootstrapEstimatesForConfidenceIntervalsInASRPerformanceEvaluation_ICASSP_2004.pdf)).
  Для пар — разница на общих высказываниях (paired), так шум набора сокращается.
- **Ошибки вызова** не выбрасываются, а перепрогоняются (`retry_failed.py`):
  иначе у движков остаются разные подмножества и сравнение перестаёт быть парным.
- **Дата прогона**: 6–7 августа 2026.

### Чего этот замер НЕ показывает

**FLEURS — чистая студийная начитка.** Один диктор, без шума, перебивок и
спонтанной речи. Реальные созвоны и телефон дадут заметно худшие цифры у всех:
в литературе для русского телефонного аудио WER доходит до 35 %.

**Цифры отсюда нельзя сравнивать с чужими бенчмарками на других наборах.**
Ставить наши 3.74 % против заявленных Deepgram 5.26 % было бы подтасовкой.
Ценность таблицы только в том, что все строки получены на одинаковом материале.

**Известные ограничения этого прогона:**

- 150 сэмплов из 775 в тестовом сплите — полный прогон готовится;
- GigaAM посчитана на 140: партнёрский эндпоинт отвалился на последних десяти
  запросах и не поднялся к моменту дозаливки;
- порядковые числительные нормализация не разбирает, так что остаточное
  отставание nova-3 (4.60 против 3.70) может быть завышено;
- задержки сняты с боевых лейнов и зависят от соседнего трафика.
