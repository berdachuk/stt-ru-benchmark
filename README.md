# Русский STT: Whisper на своих GPU против Deepgram

Открытый замер точности распознавания русской речи. Пять движков, один и тот же
набор файлов, одна и та же нормализация текста, воспроизводимый код.

Повод простой: **публичных цифр WER по русскому языку у Deepgram нет** — ни в
документации, ни в маркетинге. Есть общий показатель 5.26 % (англоцентричный) и
заявление «мы лучше Whisper на 7 языках из 7» без раскладки. Поэтому мы измерили
сами.

> **Статус: предварительный прогон, 150 сэмплов.** Полный прогон на всём тестовом
> сплите готовится. Выводы ниже даны с оговорками, которые они заслуживают —
> см. [«Чего этот замер не показывает»](#чего-этот-замер-не-показывает).

*English summary: an open WER/CER benchmark of Russian speech recognition —
self-hosted Whisper large-v3 vs Deepgram Nova-2/Nova-3 on FLEURS-ru, identical
audio bytes and identical text normalization for every engine. Harness, raw
results and methodology references are in this repo.*

## Результаты

**FLEURS-ru (test), первые 150 сэмплов, 28.4 минуты аудио. Ноль ошибок вызова.**

| движок | WER | CER |
|---|---:|---:|
| Deepgram nova-2 | **3.67 %** | 1.12 % |
| Whisper large-v3 (свои GPU) | **3.74 %** | **1.02 %** |
| WhisperX-пайплайн (VAD + выравнивание, свои GPU) | 3.74 % | 1.02 % |
| Deepgram nova-3 | 6.51 % | 4.42 % |
| Whisper-turbo, RU файн-тюн | 8.65 % | 1.80 % |

Скорость измерена по-разному и в одну таблицу с точностью не ставится:

| движок | режим вызова | медиана | RTF |
|---|---|---:|---:|
| Whisper large-v3 | один POST | 1.18 с | 0.11 |
| Whisper-turbo RU | один POST | 1.43 с | 0.133 |
| Deepgram nova-3 / nova-2 | один POST | 1.83 / 1.85 с | 0.171 / 0.223 |
| WhisperX-пайплайн | upload → очередь → поллинг | 3.79 с | 0.348 |

Последняя строка **несравнима** с остальными: в неё входят загрузка файла,
ожидание в очереди и поллинг статуса с шагом 2 секунды, а не время инференса.

### Что из этого можно утверждать, а что нет

**1. Self-hosted Whisper держится вровень с коммерческим API.** Разница с nova-2 —
0.07 процентного пункта. Это **не** доказанный паритет: доверительных интервалов
мы пока не считали, а на 150 сэмплах сотые доли процента — это единицы словесных
ошибок. Честная формулировка: на этой выборке различие мало, и данных, чтобы
объявить победителя, недостаточно.

**2. Разрыв Nova-3 — это форматирование чисел, а не качество слуха.** Первая
версия этого README утверждала, что флагман Deepgram «хуже на русском вдвое».
Это было неверно. Разбор расхождений показал:

```
эталон : в 1990 году он был добавлен в список всемирного наследия
nova-3 : в тысяча девятьсот девяностом году он был добавлен …          [WER 15%]

эталон : за ночь было изготовлено 150 200 копий
nova-3 : за ночь было изготовлено сто пятьдесят двести копий           [WER 33%]
```

Речь распознана верно. Nova-3 пишет числа словами, эталон FLEURS — цифрами,
и штраф идёт за формат записи. Nova-2 пишет цифрами и потому «выигрывает».
Косвенный признак был виден сразу в метриках: у nova-3 CER 4.42 % при WER 6.51 %,
тогда как у остальных движков CER ниже WER в 3–4 раза.

Это известная ловушка — ей посвящена отдельная работа,
[«What is lost in Normalization?»](https://arxiv.org/abs/2409.02449). Полный
прогон будет включать нормализацию числительных, и только после неё можно будет
что-то говорить о месте Nova-3.

**3. Метрика может измерять баг, а не качество.** RU-файн-тюн Whisper-turbo
показал 8.65 %. Разбор расхождений показал, что модель **вставляет пробел внутрь
слова** при декодировании:

```
телевизион ные · обнаруж ены · передав аться · выб орочно · прив ести
```

Речь распознана верно, слово разорвано. Для WER это двойной штраф — и замена, и
вставка. Дефект встретился **62 раза на 52 из 150 сэмплов** (35 % записей), у
large-v3 — один раз.

**8.65 % — это и есть продакшн-результат**, именно его получает пользователь.
Ниже — только диагностика, а не альтернативная оценка модели.

<details>
<summary>Диагностика: какая часть WER приходится на этот дефект (oracle)</summary>

Если склеить разорванные слова, **сверяясь с эталоном**, WER падает с 8.65 % до
4.36 %. Это **oracle-число с утечкой правильного ответа**: так починить в проде
нельзя, эталона там нет. Оно отвечает только на вопрос «какая доля ошибок —
разрывы, а не распознавание», и ответ: примерно половина. Ставить 4.36 % в одну
таблицу с остальными движками было бы нечестно.

Данные — в [`results/split_bug.json`](results/split_bug.json).
</details>

Общая мораль обоих случаев: прежде чем делать вывод «модель хуже», посмотрите на
сами расхождения. Дважды подряд метрика мерила форматирование, а не слух.

## Как воспроизвести

```bash
pip install -r requirements.txt

# свои модели через OpenAI-совместимый API
K=<ключ> python harness/stt_bench.py --limit 150

# Deepgram nova-3 и nova-2
DG=<ключ deepgram> LIMIT=150 python harness/dg_bench.py

# WhisperX-пайплайн (upload → poll → текст)
SC=<токен> LIMIT=150 python harness/sc_bench.py

# диагностика: какая часть WER приходится на разрывы слов
K=<ключ> LIMIT=150 python harness/stt_split_bug.py
```

Результаты — в [`results/`](results/).

## Методика

- **Набор**: [`google/fleurs`](https://huggingface.co/datasets/google/fleurs)
  ([Conneau et al., 2022](https://arxiv.org/abs/2205.12446)), конфигурация
  `ru_ru`, сплит `test`, первые 150 сэмплов по порядку, без отбора.
- **Аудио**: файлы отправляются **байт в байт**, без пересжатия и ресемплинга.
  Транспорт при этом разный (multipart против raw body) — одинаковы именно
  исходные байты.
- **Нормализация** (одинаковая для эталона и гипотезы): нижний регистр, `ё→е`,
  снятие пунктуации, схлопывание пробелов. Смысл — штрафовать за неверно
  распознанное слово, а не за оформление; тот же принцип, что у
  [нормализатора Whisper](https://arxiv.org/abs/2212.04356) и
  [Open ASR Leaderboard](https://arxiv.org/abs/2510.06961).
  🔴 **Числительные пока не нормализуются** — см. вывод 2 выше.
- **Метрики**: `jiwer`, корпусный WER по словам и CER по символам (суммарные
  ошибки к суммарной длине, а не среднее по сэмплам).
- **Задержка**: полное время запроса со стороны клиента, вместе с сетью и
  очередью, а не время инференса.
- **Дата прогона**: 6 августа 2026.

### Чего этот замер НЕ показывает

**FLEURS — чистая студийная начитка новостных фраз.** Один диктор, без шума,
перебивок и спонтанной речи. Реальные созвоны и телефон дадут заметно худшие
цифры у всех движков: в литературе для русского телефонного аудио WER доходит
до 35 %.

**Цифры отсюда нельзя сравнивать с чужими бенчмарками на других наборах.**
Ставить наши 3.74 % против заявленных Deepgram 5.26 % было бы подтасовкой — это
разные наборы и разная сложность. Ценность таблицы только в том, что все строки
получены на одинаковом материале.

**Известные ограничения этого прогона**, которые закрываются в полном:

- нет доверительных интервалов — планируется paired bootstrap
  ([Bisani & Ney, ICASSP 2004](http://www-i6.informatik.rwth-aachen.de/PostScript/InterneArbeiten/Bisani_BootstrapEstimatesForConfidenceIntervalsInASRPerformanceEvaluation_ICASSP_2004.pdf));
- не нормализованы числительные — из-за этого позиция Nova-3 некорректна;
- в `results/` только агрегаты, без построчных `ref`/`hyp`;
- 150 сэмплов вместо полного тестового сплита (775).
